The four-line brief

  1. View: What can the player see? Choose a trial base viewport.
  2. Framing: How tall is the character relative to that view?
  3. Identity: Which shapes or features must survive simplification?
  4. Test: Which small draft will you inspect in context before committing to the grid?

Hypothetical: 96-pixel-tall artwork in a 360-pixel-tall design view occupies 26.7% of its height. Enlarging the whole view by 3× makes it 288 display pixels tall, still 26.7%. Assumes 1× camera/sprite scaling and no additional display transform.

What to remember

  • The canvas can include transparent space. Measure the character too.
  • Editor zoom changes your view. Resampling changes the image grid.
  • Enlarging existing pixels does not create newly drawn detail.
  • First shape and large light/dark areas; then important features; texture last.
  • A sprite can be rectangular and span multiple environment tiles.
  • Keep compatible character scale, feet/ground reference and motion room across frames.

Before selecting a production size

Can you recognize the character at the intended game-view size? Is there room for attacks and enemies? Do important features merge? Test a clearer simplification, another grid or different framing. Size selection is a trial supported by appearance and runtime evidence.
