Make one trustworthy export

  1. Check the visible stack.Keep the original character’s art layers and Corrections visible at their intended opacity. Leave guide-source-seed (hidden) hidden. Hide any extra ordinary guide, reference photo or color-test background you added. For this cleanup route, the character base stays visible; it is final art, not a disposable guide. Layer visibility ↗
  2. Save the native master first.Use File → Save. Confirm that you are saving my-first-correction.aseprite, with the separate Corrections row. If you have only a PNG open, use File → Save As… and choose .aseprite before continuing. Save ↗
  3. Export the visible picture.Use File → Export → Export As…, choose practice/my-first-correction.png, and keep output scale at 100% or 1×. It is a single-frame 128 × 192 exercise. If your build presents different export options, choose a single PNG at native size. Do not add a background fill. Exporting ↗
  4. Reopen the PNG in Aseprite.Check the dimensions, the little tote patch, and transparent space outside the character. A checkerboard shown by the editor usually represents transparency; a checkerboard actually painted into an imported image is still opaque artwork. If uncertain, put a temporary solid-color layer underneath this reopened PNG: transparent space reveals the color. Close this test tab without saving the background into your PNG.

One important tracing check

For a full redraw, hide its guide and inspect your new drawing alone before export. If only one tote edge remains, the trace is still partial. For a cleanup, retain the complete base. These two workflows need different visible layers.

How this becomes a sprite in Godot

The PNG supplies the visible pixels. A Sprite2D node displays those pixels. For an optional first static test in a separate Godot 4 practice project:

  1. Copy your PNG into the project folder.For example, put it in art/my-first-correction.png. Godot imports it and lists it in the FileSystem dock. Keep .aseprite as your source file; this simple path uses the PNG directly.
  2. Add a Sprite2D to a 2D scene.Select the node and drag the imported PNG onto its Texture property. You now have a static visual. It does not add movement, collision, combat or animation. Sprite2D ↗
  3. Keep pixel edges crisp.In the Sprite2D Inspector, find its inherited CanvasItem Texture → Filter setting, usually by expanding the Texture section or searching for “filter”, and choose Nearest. In Godot 4 this filtering control is on the node, with a project default; older tutorials may show it in Import. For pixel art, lossless image compression is the documented recommendation. Texture Filter ↗ · Image import ↗
  4. Judge the game view.Use an integer scale, such as 2×, for the first crisp comparison. Check face, tote and contrast at the intended game-view size. Nearest filtering cannot restore a detail lost during resizing, and it does not by itself solve camera or subpixel movement issues.

These are documented next steps. No Godot scene was created or run as part of preparing this course. Your first actual game-view test remains to be observed.

Ask the agent: “Here is what I saw in the reopened PNG: ____. Is it ready for a Godot practice test?” You can ask for help with the import without having to build a game first.
