# Automatic first fill, then reference-guided reconstruction

Date: 30 October 2026. Status: research and proposed experiment; no artwork or editor session changed.

## Answer

**Yes: software can fill a blank native layer with every corresponding source pixel, then agents can inspect and correct the whole character.** The first fill should be deterministic and performed in bulk. Asking a model to infer or submit every color separately adds no useful judgment.

At the same grid, writing `output[x,y] = source[x,y]` for every RGBA sample produces the same raster as copying/importing that image, provided coordinates, color interpretation, alpha, opacity and blending agree. A newly drawn layer does not acquire different visual qualities merely because the samples were written individually. The useful subsequent work is choosing intentional shapes/clusters where needed, assigning meaningful part ownership, correcting reference drift, and demonstrating dependable revisions. Those tasks can create a useful native master from a source-derived fill. An unchanged flat copy establishes initialization only.

This is an extension of the existing [source-guided automation proposal](source-guided-automation.md), which already recommends full first-color transfer followed by native cleanup. The remaining experiment should address the **entire character and its editable structure**, rather than repeat a facial microcorrection benchmark. There should be no changed-pixel quota: inspect all regions, fix supported defects at their natural extent, and retain good source-derived regions.

## Different operations hidden inside “trace”

| Operation | What is automatic | What still requires judgment |
| --- | --- | --- |
| Same-resolution sample transfer | Copy each source RGBA sample to the corresponding destination location. | Whether that source is suitable; reference authority and useful structure. |
| High-resolution source → target grid | Apply a declared crop/transform and resampling filter. | Which details may merge; whether eyes, fringe and expression still read. There is no uniquely correct target color before choosing a sampling rule. |
| Palette quantization | Map colors into a chosen palette with an explicit dither policy. | Material relationships, feature contrast and acceptable simplification. Fewer colors alone do not establish pixel craft. |
| Semantic part assignment | Apply reviewed ownership masks to the transferred raster. | Which pixels belong to hair, face, jacket, strap, etc., especially at overlaps. Color or connectivity does not establish anatomy. |
| Full trace-guided reconstruction | Transfer known geometry/colors and apply recorded patches. | Deliberate contours, clusters, planes, likeness and full-character organization. It may reuse most samples without ceasing to be a useful reconstruction. |
| Hidden surfaces | Apply an authored backing/replacement drawing. | What lies behind hair, sleeves or tote; a visible raster contains no observations of those hidden samples. |
| Animation | Reuse known parts, coordinates and metadata. | New poses/surfaces, volume, expression, contacts and timing. A complete still is not an animation proof. |

Pillow documents resizing and palette mapping as separate operations; nearest sampling preserves a chosen sample, while BOX reduction combines source coverage. Neither filter makes semantic decisions. Resize before palette conversion where filtered reduction is intended: palette-mode resizing uses nearest sampling. Specify dithering rather than accepting its default. These are documented capabilities, not new local art results. [Image API](https://pillow.readthedocs.io/en/stable/reference/Image.html), [filter definitions](https://pillow.readthedocs.io/en/stable/handbook/concepts.html#filters).

## Practical implementation and comparison traps

Use an ordinary editable image layer for the new artwork. Keep any guide locked, separately named and excluded from exports. Read colors from the original image data, never from a dimmed reference layer or a screen composite. Aseprite documents image cloning, pixel access and bulk image copying; coordinates are image-local and need the cel offset when mapped to the canvas. These APIs establish feasibility, not permission to bypass the configured adapter. [Image API](https://aseprite.org/api/image), [Layer API](https://aseprite.org/api/layer).

The installed Pebbly 0.8.2 source already supports batched `pixels`, `grid`, and cross-layer `blit` operations. Its `blit` implementation reads source cel pixels with position correction and writes them into the destination; per-pixel editor round trips are unnecessary. Prepared part PNG import/duplication also has the E0 proof. Inspect current schemas and smoke-test the selected operation when implementing; this research invoked no editor tools. Local source inspected: `.art-tools/pebbly/node_modules/@pebbly/aseprite-ai-artist/dist/tools/draw.js` and `extension/ai-artist.lua`; public provenance: [upstream repository](https://github.com/with-pebbly/aseprite-ai-artist). Generic Lua remains disabled in project configuration.

- **Alpha:** copy alpha along with RGB. Leaving a second partial-alpha reference visible beneath the new art changes the composite. Do not silently threshold edges or delete every pixel of a “background” color. Preserve intentional openings and solid denim separately.
- **Hidden RGB:** RGB under zero alpha can change without any visible difference. E0 records 5,907 such normalized pixels. Compare alpha and visible colors separately from full decoded equality and file hashes.
- **Color handling:** record image mode/profile policy; indexed values are palette indices, not RGB colors. A palette lock, conversion or color-space change can break an intended exact transfer. PNG stores unassociated alpha; filtered processing must avoid invisible RGB contaminating edges. [PNG specification](https://www.w3.org/TR/png-3/#6AlphaRepresentation).
- **Alignment:** freeze crop bounds, uniform scale, rounding, padding and anchor. Use exact pixel differences only for registered same-grid controls/protected regions. The full scene, close-up and generated cutout are different views/framing; comparison resizing must be labeled and cannot turn them into equivalent ground truth.
- **Review:** show actual exports on consistent neutral mattes at 1× and integer zoom, plus source-resolution crops. Changed-pixel maps locate edits; they do not score likeness. Identity and expression remain vetoes, even when a candidate is cleaner or technically valid.

## Smallest next experiment

**Proposed, ready for a separate implementation task:** one whole-character assisted reconstruction using the existing sharp seed and canonical originals. No additional image generation or integration is needed to test this question. This is a construction study, not another model contest or a new production-grid decision.

1. **Freeze Control A.** Copy/hash the fixture and references into a new experiment directory. Keep the seed, palette, canvas, pose, framing and alpha policy fixed initially. Inspect the full character and list reference-supported defects or explicitly satisfactory regions: face/expression, hair masses, jacket/tee, denim, shoes, tote/strap and silhouette. A needed recipe/grid change becomes a separately labeled variant, not an invisible alteration of this control.
2. **Construct complete Candidate B.** Create a fresh native scaffold; generate reviewed target-grid ownership masks covering the entire visible character; fill all parts automatically from A. Start with useful face/hair/clothing/limb/tote organization rather than empty layers or a flattened base plus tiny facial overlays. Verify the untouched composite equals A before artistic work. Record masks, ownership precedence, coordinates and rebuild inputs. Agent review resolves ambiguous ownership; automatic mask discovery is optional future work.
3. **Finish the whole character.** One construction agent makes coherent reference-supported corrections wherever the audit warrants them, including substantial region redraws if necessary. An independent visual reviewer examines original/seed/best/candidate at every checkpoint, reports defects and regressions, and does not silently supply replacement art. Allow initial finishing plus two corrective checkpoints; retain failures. Escalate a repeatedly ambiguous identity/structure problem once to a stronger reviewer, or stop with the cause and next variant. Do not enlarge the budget through repeated “proof” passes.
4. **Prove useful structure.** Save/reopen/export; rebuild into a fresh destination from frozen inputs plus masks/patches. On a labeled duplicate, change a whole useful feature such as a jacket highlight plane or tote accent and prove unrelated layers/pixels remain protected. Inspect isolated parts and a diagnostic hide/move; exposed gaps must be labeled. Add only backing necessary for a declared edit/movement and record it as inferred drawing, not source sampling.
5. **Select honestly.** Deliver the full native source, transparent export, whole-character and head comparisons, per-region review, provenance, all attempts and duplicate-edit proof. Separate technical pass, agent preference and user approval. If the seed needs little visual correction, a successfully structured, revisable result is still informative; do not claim an artistic improvement that reviewers cannot see.

Success answers whether automatic full initialization followed by agent craft can deliver a convincing, practically editable **whole-character still**. It does not require changing a minimum percentage of pixels. It does require full coverage, useful ownership, direct original comparisons and observed revision/reopen evidence. Animation, hidden-surface completeness, Godot playback, final user approval, cost savings and production readiness remain separate, untested boundaries for this study.

For future references, retain this separation of deterministic transfer from artistic decisions, but select the representation from the reference: illustrated layers, vectors or rig parts need different preparation and acceptance evidence. The current pixel recipe is one test case, not the universal pipeline.
