# Shared sharp-seed sprite trial

## Task

Use the updated project workflow to produce a deliberately finished, editable
128x192 static sprite from the provided common sharp seed. Preserve the supplied
character's identity, open-eye/gaze relationship, restrained smile, pose, costume
and the user-preferred crisp pixel treatment. A seed that already satisfies a
visual property should retain it; any repair needs an observed defect and review.
Choose your own artistic corrections and useful native part organization.

The exact input paths and hashes are in shared/fixture.json, supplied once the
fixture is verified. Both contestants receive the identical seed, ordered palette,
one-layer native baseline and original references. Keep the common crop, native
grid, framing, palette and alpha policy fixed. Changing preparation is a separate
study and does not belong inside this comparison. No new image generation.

Approved scene/close-up are identity/style authorities. The generated transparent
full-character image supplies production geometry; its differences are not newly
approved design changes. Review original, seed and actual native export at 1x and
integer zoom and record the seed-use decision before dependent corrections.

## Instructions and isolation

Read repository AGENTS.md, applicable art-production workflow, asset contract,
style/motion guidance and installed pixel-art-director skill. This controlled test
uses shared/trial-context.md as its scoped CONTEXT/handoff briefing instead of the
historical experiment narrative: it retains required goals/preservation/authority
rules while excluding prior operation coordinates and contestant outcomes. Read
GLOSSARY.md and relevant ADR. Do not inspect old converted/corrected artwork,
correction scripts, trial results, opponent files or historical art ledgers. Do not
contact other agents or spawn helpers. Only your assigned directory is writable.
Leave shared inputs, all originals, global configuration and handoff untouched.

The workflow is reference-driven, not a universal sharp/pixel recipe: the sharp
recipe is a user-selected control for this particular test. Other reference styles
are handled by the general intake and separately chosen construction route.

Use only the existing dedicated authorized Aseprite MCP for native operations; no
UI, Code-MCP, generic Lua enablement or direct Aseprite CLI fallback. Local
deterministic preparation/analysis scripts are allowed. Wait for an explicit
editor-slot grant before any Aseprite call, including preflight; only use your own
documents and explicit document identifiers. No editor mode switches.

## Equal limits and review loop

Each trial has at most three artistic exports (initial plus two corrections) and
120 Aseprite/editor calls in total, including smoke tests, failures and proof work.
Keep all attempts. Exported rejected candidates still consume a pass. Record
actual call usage; unknown provider compute/cost remains unknown.

For each pass retain native source, PNG, exact operation inputs and technical
checks. Save original/seed/best-prior/new candidate comparisons at 1x and equal
integer zoom, including readable head crops and full-body context. Verify labels,
matte behavior and exact export provenance before making a visual selection.
Record identity/expression, pixel craft and native/technical results separately.
Name the best eligible candidate, latest status and next baseline explicitly. A
failed expression cannot be outweighed by technical gains; no eligible result is
an allowed outcome. A later pass is not automatically better or selected.

Send each artistic checkpoint to the supervisor and release the editor slot.
Wait for defect-only feedback before another pass; decide the repair yourself.
No solution coordinates, colors, prepared art patches or outside critic model
will be supplied. You may prepare locally while editor access is paused.

Demonstrate native reopen/export equality and a useful localized edit on a
labelled duplicate, with protected native/pixel data checked. Proof duplicates
are not artistic passes; their calls count. Preserve the selected candidate.
Stop at budget limits or when no justified improvement remains. Deliver selected
and last-attempted artifacts separately, or explicitly none selected. User approval,
animation, Godot/runtime and production readiness are separate and unperformed.
