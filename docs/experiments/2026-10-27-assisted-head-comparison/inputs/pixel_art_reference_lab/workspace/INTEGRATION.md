### Resolve the old restriction explicitly
Use a positive rule: reference-derived pixels, masks and traces are permitted starting material; the delivered native asset must have the structure and verified revisions required by its use. Keep raw inputs separate and label construction provenance. An imported flat seed is a seed—not proof of completed layered production.

Do not erase the user's earlier feedback that a particular flat background looked inconsistent. That specific failure is not a permanent ban on every reference-assisted method.

### Keep the integration small
The kit's `scripts/reference_lab.py` is optional preparation tooling. Prefer existing repository functions for direct-reference reviews and native verification. Reuse or extend instead of duplicating. Review tests and run them before adopting code. Do not weaken native checkers, hard-code automatic art scores, or install a new editor/MCP by default.

No ADR must change merely because a kit exists. Document the user's new permitted methods, label proposed defaults as provisional, and record technical decisions when the evidence actually supports them. Do not turn every routine step into another user-approval gate.
