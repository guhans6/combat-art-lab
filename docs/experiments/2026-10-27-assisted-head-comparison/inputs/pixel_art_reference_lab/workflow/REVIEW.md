# Review record — keep technical and artistic judgments separate

For each candidate, record the reference roles, exact files, native grid, mapping, intended display size, route, pass number and inspected comparison.

| Dimension | Record concrete observations |
|---|---|
| Identity | Face shape, eye relation, hair mass/fringe and distinctive costume relationships |
| Expression | Intended emotion, lid/brow/mouth relationships, pose-specific changes |
| Style | Cluster size, material-related outlines, shading planes, palette relationships and detail density |
| Silhouette/proportions | Head/body relationships, negative spaces, orientation and pose |
| Atmosphere/context | Character/background compatibility, lighting treatment and readability |
| Native editability | Meaningful structure and observed isolated edit; import/trace/cleanup provenance |
| Temporal coherence | Frame-to-frame scale, volume, palette, root/contact motion and timing, if tested |
| Runtime | Actual engine version, scene, playback and scale observations, if tested |

State `continue`, `correct`, `reject` or `ready for user selection`, with a reason. Do not convert these dimensions into a numerical universal art score. Do not present a silhouette IoU as a likeness percentage.

Technical equality checks apply to protected areas and unchanged originals. They do not require a newly constructed asset to match the original raster. Differences are acceptable where they implement the requested pose/expression or useful simplification without identity/style drift.

User approval must identify the concrete viewed artifact. Agent selection of a provisional candidate is not user approval. A normalizing/exporting script completing does not prove artistic quality or gameplay suitability.
