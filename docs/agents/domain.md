# Domain documentation

This is a single-context repository.

Before domain exploration, read the root [GLOSSARY.md](../../GLOSSARY.md) and relevant decisions under docs/adr. [CONTEXT.md](../../CONTEXT.md) records current goals and open choices; it does not replace the glossary.

Use glossary terms consistently in issues, hypotheses, source, and test names. If a concept is missing, decide whether it is a real domain term before adding it. Use domain-modeling for terminology or decision work.

Read ADRs relevant to the current area. Surface a proposed contradiction and its evidence explicitly rather than silently overriding an accepted decision.

On a new host or checkout where an optional domain document is absent, proceed with the available evidence. Create new domain material when terms or decisions are actually resolved.
