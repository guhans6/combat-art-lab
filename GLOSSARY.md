# Glossary

| Term | Meaning here |
| --- | --- |
| Concept candidate | An image used to explore a design or style; not automatically a production asset. |
| Approved reference | A specific visual artifact the user accepted as guidance, with the accepted qualities recorded. |
| Style guide | Observable rules for appearance: silhouette, proportions, palette, rendering, and scale. |
| Motion guide | Rules for poses, timing, movement character, contact, recovery, and effects. |
| Native master | The meaningful editable source: for example a layered Aseprite file, a 2D rig, or a model and animation scene. |
| Construction source | Scripts, pixel grids, drawing operations, or rig parameters used to create and revise the native master. |
| Runtime export | Frames, sprite sheet, textures, and metadata consumed by Godot; separate from source deliverables. |
| Sprite | A 2D visual used by the game. A sprite does not imply a particular pixel resolution or editing structure. |
| Frame | A displayed image/state of an animation. Frame count and playback duration are separate decisions. |
| Cel | Image content on a particular layer and animation frame in a frame-based editor. |
| Anchor | The stable reference used to position a character or frame, such as the intended ground contact. |
| Anticipation | The preparation that makes an upcoming action readable. |
| Active/contact interval | The gameplay interval in which an attack can connect, coordinated with its visual strike. |
| Recovery | The motion and time after the strike before returning to the intended next state. |
| Pipeline proof | A small observed construction, playback, and revision experiment used to assess a method. |
| Visual approval | The user's acceptance of a specific result; agents must not fabricate it. |
| Checkpoint | A verified increment. It is not automatically another human permission gate. |
